Ubuntu 22.04 클린 설치 PC - FeDiT 예측매니저 설치 명령어 순서
================================================================

작성 기준
- Ubuntu 22.04 LTS x86_64 단일 서버
- FeDiT 저장소: https://github.com/etri/FeDiT.git
- 브랜치: OPFW_development_ETRI_pman
- 검증 기준 커밋: 2085a2c31d080d53127b40345359c18281852f0b
- Kubernetes 1.30.14, Kubeflow 1.9.1, KServe, KubeRay 필수 설치
- NVIDIA 드라이버, NVIDIA Container Toolkit, NVIDIA Device Plugin, DCGM Exporter 설치 제외

사용 방법
1. 이 파일은 Ubuntu 터미널에서 위에서 아래 순서로 사용한다.
2. 명령 블록을 단계별로 복사하여 실행한다. 파일 전체를 한 번에 붙여넣지 않는다.
3. 0절의 INSTALL_PROFILE과 파일 경로를 먼저 확인한다.
4. FULL은 CPU 4코어, 메모리 32GiB, 디스크 여유 200GiB 이상에서 사용한다.
5. LOW_RESOURCE는 CPU 4코어, 메모리 8GiB, 8GiB swap, 디스크 여유 80GiB 이상에서 사용한다.
6. 예측매니저_설치_스크립트_클린설치_보완본.zip은 사전에 Ubuntu PC의 Downloads 디렉터리에 복사한다.
7. 저장소가 비공개이면 GitHub 접근 권한과 HTTPS 토큰 또는 SSH 키를 먼저 준비한다.
8. 같은 터미널에서 계속 진행한다. 새 터미널을 열었으면 0절의 export 명령을 다시 실행한다.

3-A. Git으로 지정 브랜치와 검증 커밋 받기
-----------------------------------------

# SOURCE_METHOD=GIT일 때만 실행한다.
if [ "$SOURCE_METHOD" = "GIT" ]; then
  git ls-remote --heads "$FEDIT_REPO_URL" "$FEDIT_BRANCH"
  git clone --branch "$FEDIT_BRANCH" --single-branch --depth 1 \
    "$FEDIT_REPO_URL" "$FEDIT_ROOT"

  if ! git -C "$FEDIT_ROOT" cat-file -e "${REFERENCE_COMMIT}^{commit}" 2>/dev/null; then
    git -C "$FEDIT_ROOT" fetch --depth 1 origin "$REFERENCE_COMMIT" || \
      git -C "$FEDIT_ROOT" fetch --unshallow origin
  fi

  git -C "$FEDIT_ROOT" checkout --detach "$REFERENCE_COMMIT"
  test "$(git -C "$FEDIT_ROOT" rev-parse HEAD)" = "$REFERENCE_COMMIT"
  git -C "$FEDIT_ROOT" branch --contains "$REFERENCE_COMMIT" || true
fi


3-B. 브라우저에서 받은 FeDiT.zip 압축 풀기
-------------------------------------------

# SOURCE_METHOD=ZIP일 때만 실행한다.
# GitHub에서 Code -> Download ZIP으로 받은 파일을 FEDIT_ZIP 경로에 둔다.
if [ "$SOURCE_METHOD" = "ZIP" ]; then
  test -f "$FEDIT_ZIP"
  export FEDIT_UNPACK_ROOT="$WORK_ROOT/fedit-zip-unpack"
  test ! -e "$FEDIT_UNPACK_ROOT"
  mkdir -p "$FEDIT_UNPACK_ROOT"
  unzip -q "$FEDIT_ZIP" -d "$FEDIT_UNPACK_ROOT"

  export FEDIT_EXTRACTED_DIR
  FEDIT_EXTRACTED_DIR="$(find "$FEDIT_UNPACK_ROOT" -mindepth 1 -maxdepth 1 -type d -print -quit)"
  test -n "$FEDIT_EXTRACTED_DIR"
  mv "$FEDIT_EXTRACTED_DIR" "$FEDIT_ROOT"
fi

test -d "$FEDIT_ROOT"
test -f "$PM_ROOT/Dockerfile"
test -f "$PM_ROOT/requirements.txt"
test -f "$PM_FRONT_ROOT/package.json"
test -f "$PM_FRONT_ROOT/nginx.conf"

# Dockerfile은 설치 스크립트 압축이 아니라 외부에서 받은 FeDiT 소스에 있다.
# 외부 ZIP 또는 git clone 사용은 정상이며, 설치 설정에서 아래 두 경로를 넘긴다.
printf 'Prediction Manager Dockerfile=%s\nFrontend root=%s\n' \
  "$PM_ROOT/Dockerfile" "$PM_FRONT_ROOT"

printf '%s\n' \
  "repository=$FEDIT_REPO_URL" \
  "branch=$FEDIT_BRANCH" \
  "reference_commit=$REFERENCE_COMMIT" \
  "source_method=$SOURCE_METHOD" \
  > "$WORK_ROOT/fedit-source-info.txt"

if [ -d "$FEDIT_ROOT/.git" ]; then
  test "$(git -C "$FEDIT_ROOT" rev-parse HEAD)" = "$REFERENCE_COMMIT"
  git -C "$FEDIT_ROOT" rev-parse HEAD | tee "$WORK_ROOT/fedit-source-commit.txt"
else
  printf '%s\n' "$REFERENCE_COMMIT" | tee "$WORK_ROOT/fedit-source-commit.txt"
fi

curl -fsS -X POST \
  -H "kubeflow-userid: ${ADMIN_EMAIL}" \
  "http://127.0.0.1:18000/api/admin/users/kubeflow-user-example-com/tenant-resources/reconcile" \
  | jq -e '.status == "reconciled"'
kubectl -n kubeflow-user-example-com scale deployment/pm-mlflow --replicas=0
kubectl -n kubeflow-user-example-com scale statefulset/nifi --replicas=0
kubectl -n kubeflow-user-example-com delete raycluster pm-ray \
  --ignore-not-found --wait=false
kubectl -n kubeflow-user-example-com get deployment/pm-mlflow statefulset/nifi

# 15-A. NiFi 시작
kubectl -n kubeflow-user-example-com scale statefulset/nifi --replicas=1
kubectl -n kubeflow-user-example-com wait --for=condition=ready \
  pod -l app=nifi --timeout=300s
sudo systemctl stop nifi-forward.service 'nifi-forward-*.service' >/dev/null 2>&1 || true
sudo systemd-run --collect --unit="nifi-forward-$(date +%s)" \
  --property=Restart=always --property=RestartSec=2 \
  --setenv=KUBECONFIG=/etc/kubernetes/admin.conf \
  /usr/bin/kubectl -n kubeflow-user-example-com port-forward --address=0.0.0.0 \
  service/nifi 15001:8080

# NiFi 종료
sudo systemctl stop nifi-forward.service 'nifi-forward-*.service' >/dev/null 2>&1 || true
kubectl -n kubeflow-user-example-com scale statefulset/nifi --replicas=0


# 15-B. Label Studio 시작
kubectl -n kubeflow scale deployment/label-studio --replicas=1
kubectl -n kubeflow rollout status deployment/label-studio --timeout=600s
sudo systemctl stop label-studio-forward.service 'label-studio-forward-*.service' >/dev/null 2>&1 || true
sudo systemd-run --collect --unit="label-studio-forward-$(date +%s)" \
  --property=Restart=always --property=RestartSec=2 \
  --setenv=KUBECONFIG=/etc/kubernetes/admin.conf \
  /usr/bin/kubectl -n kubeflow port-forward --address=0.0.0.0 \
  service/label-studio 15003:80

# Label Studio 종료
sudo systemctl stop label-studio-forward.service 'label-studio-forward-*.service' >/dev/null 2>&1 || true
kubectl -n kubeflow scale deployment/label-studio --replicas=0


# 15-C. MLflow 시작
kubectl -n kubeflow-user-example-com scale deployment/pm-mlflow --replicas=1
kubectl -n kubeflow-user-example-com rollout status deployment/pm-mlflow --timeout=600s
sudo systemctl stop mlflow-forward.service 'mlflow-forward-*.service' >/dev/null 2>&1 || true
sudo systemd-run --collect --unit="mlflow-forward-$(date +%s)" \
  --property=Restart=always --property=RestartSec=2 \
  --setenv=KUBECONFIG=/etc/kubernetes/admin.conf \
  /usr/bin/kubectl -n kubeflow-user-example-com port-forward --address=0.0.0.0 \
  service/pm-mlflow 15000:5000

# MLflow 종료
sudo systemctl stop mlflow-forward.service 'mlflow-forward-*.service' >/dev/null 2>&1 || true
kubectl -n kubeflow-user-example-com scale deployment/pm-mlflow --replicas=0


# 15-D. Ray 생성과 시작
curl -fsS -X POST \
  -H "kubeflow-userid: ${ADMIN_EMAIL}" \
  "http://127.0.0.1:18000/api/admin/users/kubeflow-user-example-com/tenant-resources/reconcile" \
  | jq .
kubectl -n kubeflow-user-example-com wait --for=condition=ready \
  pod -l ray.io/node-type=head --timeout=600s
sudo systemctl stop ray-forward.service 'ray-forward-*.service' >/dev/null 2>&1 || true
sudo systemd-run --collect --unit="ray-forward-$(date +%s)" \
  --property=Restart=always --property=RestartSec=2 \
  --setenv=KUBECONFIG=/etc/kubernetes/admin.conf \
  /usr/bin/kubectl -n kubeflow-user-example-com port-forward --address=0.0.0.0 \
  service/pm-ray-head-svc 15002:8265

# Ray 종료
sudo systemctl stop ray-forward.service 'ray-forward-*.service' >/dev/null 2>&1 || true
kubectl -n kubeflow-user-example-com delete raycluster pm-ray \
  --ignore-not-found --wait=true


# 15-E. Prometheus 시작
kubectl -n monitoring scale deployment/kube-prometheus-stack-operator --replicas=1
kubectl -n monitoring scale statefulset/prometheus-kube-prometheus-stack-prometheus --replicas=1
kubectl -n monitoring rollout status deployment/kube-prometheus-stack-operator --timeout=900s
kubectl -n monitoring rollout status statefulset/prometheus-kube-prometheus-stack-prometheus --timeout=900s
sudo systemctl stop prometheus-forward.service 'prometheus-forward-*.service' >/dev/null 2>&1 || true
sudo systemd-run --collect --unit="prometheus-forward-$(date +%s)" \
  --property=Restart=always --property=RestartSec=2 \
  --setenv=KUBECONFIG=/etc/kubernetes/admin.conf \
  /usr/bin/kubectl -n monitoring port-forward --address=0.0.0.0 \
  service/kube-prometheus-stack-prometheus 19090:9090
curl -fsS "http://127.0.0.1:19090/-/ready"
curl -fsSG "http://127.0.0.1:19090/api/v1/query" \
  --data-urlencode 'query=up' | jq -e '.status == "success"'

# Prometheus 종료
sudo systemctl stop prometheus-forward.service 'prometheus-forward-*.service' >/dev/null 2>&1 || true
kubectl -n monitoring get deployment -o name | \
  xargs -r kubectl -n monitoring scale --replicas=0
kubectl -n monitoring get statefulset -o name | \
  xargs -r kubectl -n monitoring scale --replicas=0


# 15-F. Knative/KServe 시작
kubectl -n kubeflow scale deployment/kserve-controller-manager --replicas=1
kubectl -n kubeflow rollout status deployment/kserve-controller-manager --timeout=600s
kubectl -n knative-serving scale deployment \
  activator autoscaler controller net-istio-controller net-istio-webhook webhook \
  --replicas=1
kubectl -n knative-serving get pods

# Knative/KServe 종료
kubectl -n knative-serving scale deployment \
  activator autoscaler controller net-istio-controller net-istio-webhook webhook \
  --replicas=0
kubectl -n kubeflow scale deployment/kserve-controller-manager --replicas=0

18. 설치 완료 기준
------------------

- kubectl get nodes에서 단일 노드가 Ready이다.
- Kubeflow, KServe와 KubeRay CRD가 조회된다.
- Prediction Manager의 /healthz가 HTTP 200을 반환한다.
- 예측기 생성/연동 도구가 18080 포트에서 열린다.
- FULL 환경에서는 NiFi, Ray, MLflow와 Label Studio가 동시에 열린다.
- LOW_RESOURCE 환경에서는 필요한 서비스만 15절 명령으로 시작하고 점검 후 종료한다.
- NVIDIA 관련 패키지와 드라이버는 설치하지 않는다.
