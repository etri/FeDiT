FeDiT 예측매니저 호스트 설치 가이드
=====================================

문서 범위와 검증 상태
---------------------
- Ubuntu 22.04 LTS x86_64 호스트에서 일반 sudo 사용자로 설치하는 방법이다.
- Docker 컨테이너에 접속하여 설치하는 방법은 다루지 않는다.
- 한 호스트에는 CPU 모드 또는 GPU 모드 중 하나만 설치한다.
- 설치 과정은 메모리 용량을 설치 중단 조건으로 사용하지 않는다.
- CPU/GPU 설치 및 기능 시험은 반드시 서로 분리된 클린 환경에서 수행한다.
- 데이터셋 기반 KFP 재학습과 AutoML 원클릭 서빙은 8절의 선행 조건을 먼저
  충족해야 한다. 화면만 열리는 상태는 기능 시험 성공이 아니다.
- NVIDIA 드라이버는 이 설치 과정에서 설치, 업데이트 또는 재설치하지 않는다.


1. 설치 전 확인
----------------

필수 조건:

- Ubuntu 22.04 LTS x86_64
- CPU 4 core 이상
- 루트 파티션 여유 공간 200 GiB 이상
- 인터넷 연결
- sudo 권한을 가진 일반 사용자

메모리는 기록만 하며 설치 거부 조건이 아니다. CPU 모드는 작은 메모리의
단일 노드에서도 모든 메뉴를 유지하도록 작은 Kubernetes 요청값과 CPU swap
프로필을 자동 적용한다. 실제 운영에서는 동시에 실행할 작업 수에 맞는 CPU,
메모리와 디스크 여유 공간을 확보한다.

GPU 모드에서는 설치 전에 다음 명령이 정상 동작해야 한다.

  nvidia-smi

GPU 모드는 호스트의 GPU 개수, 모델명, 드라이버 버전과 최소 VRAM을
`nvidia-smi`에서 읽는다. 최소 VRAM을 12 GiB 단위로 나누어 GPU당
time-slicing 슬롯을 계산하고, 결과를 1~8 범위로 제한한다. 드라이버가 없거나
`nvidia-smi`가 실패하면 GPU 모드를 실행하지 않는다.


2. FeDiT 다운로드와 코드 배치
-------------------------------

호스트 터미널에서 다음 명령을 실행한다.

  sudo apt-get update
  sudo DEBIAN_FRONTEND=noninteractive apt-get install -y ca-certificates curl git unzip
  INSTALL_USER="${SUDO_USER:-$USER}"
  INSTALL_HOME="$(getent passwd "$INSTALL_USER" | cut -d: -f6)"
  mkdir -p "$INSTALL_HOME/prediction-manager-work"
  cd "$INSTALL_HOME/prediction-manager-work"
  git clone -b OPFW_development_ETRI_pman --single-branch https://github.com/etri/FeDiT.git

이후 절의 명령도 같은 터미널에서 실행한다. 새 터미널을 열었다면 위의
`INSTALL_USER`, `INSTALL_HOME` 두 줄을 먼저 다시 실행한다. 설치 스크립트는
sudo로 실행되어도 이 실제 사용자 홈을 판별해 사용하며 `/root`에 사용자 작업
파일을 만들지 않는다.

Private repository 인증은 Git credential manager, SSH key 또는 Git의 대화형
인증을 사용한다. 비밀번호나 access token을 명령행, URL, 설정 파일 또는 설치
로그에 직접 기록하지 않는다.

제공된 코드 압축파일의 최상위 폴더는 `OPFW`이다. 압축을 푼 뒤 그 `OPFW`
폴더를 다음 FeDiT 저장소의 `OPFW`에 덮어쓴다.

  "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW"

설치 스크립트 폴더는 다음과 같다.

  "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts"


3. 사용할 포트
---------------

외부 또는 브라우저 접속에 사용하는 TCP 포트는 아래 여섯 개뿐이다.

  15000, 15001, 15002, 15003, 18000, 19090

설치기는 UFW 또는 firewalld가 활성화된 경우 위 포트만 자동 허용한다.
공유기, 사내 방화벽, 클라우드 보안 그룹은 설치기가 바꾸지 않으므로 필요한
접속 범위에서 같은 포트를 별도로 허용한다.

Kubernetes NodePort, 로컬 이미지 Registry, Prediction Manager 상태 점검 포트는
호스트 외부에 공개하지 않는다. 18080, 30080, 30081은 사용하지 않는다.


4. 실행 권한 부여
------------------

설치 전에 한 번만 실행한다.

  cd "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts"
  chmod +x ./*.sh ./scripts/*.sh


5. CPU 모드 설치
----------------

CPU 모드는 NVIDIA GPU, NVIDIA 드라이버, NVIDIA Container Toolkit, Device
Plugin, DCGM Exporter를 사용하거나 설치하지 않는다. Ray는 CPU 작업만
실행한다.

다음 두 명령을 순서대로 실행한다.

  cd "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts"
  sudo ./01-install-required-modules-cpu.sh
  sudo ./02-start-prediction-manager-cpu.sh

`01-install-required-modules-cpu.sh`는 Ubuntu 필수 패키지, Docker,
containerd, Kubernetes 도구, Helm 및 Kustomize를 설치한다.

`02-start-prediction-manager-cpu.sh`는 Kubernetes와 예측매니저 서비스를
구성하고 다음을 확인한 뒤 종료한다.

- Kubernetes API
- Prediction Manager deployment Ready
- FeDiT 및 Prediction Manager HTTP 진입
- CPU 전용 모드

완료 후에는 8절의 CPU 기능 전수 점검을 실행하고, 설치 대상 컨테이너 또는
호스트를 재시작한 뒤 같은 점검을 한 번 더 실행한다. 재시작 뒤에는 FeDiT HTTP
200, Prediction Manager health API, 모든 Kubernetes Pod Ready 및 여섯 공개
포트를 함께 확인한다.


6. GPU 모드 설치
----------------

GPU 모드는 기존 NVIDIA 드라이버가 정상이고 `nvidia-smi`가 동작하는
호스트에서만 사용한다. 설치 스크립트는 드라이버를 바꾸지 않고 NVIDIA
Container Toolkit, Kubernetes Device Plugin, DCGM Exporter와 GPU
time-slicing만 구성한다.

다음 두 명령을 순서대로 실행한다.

  cd "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts"
  sudo ./01-install-required-modules.sh
  sudo ./02-start-prediction-manager.sh

GPU 개수나 모델명을 스크립트 또는 설정 파일에 직접 입력할 필요가 없다.
다른 PC에서 실행할 때도 실행 시점의 `nvidia-smi` 결과를 사용한다.

완료 후에는 8절의 GPU 기능 전수 점검을 실행한다. 이 점검은 GPU Device Plugin
할당량, CUDA Driver API, GPU Ray 작업 및 DCGM Prometheus metric을 실제로
확인한다. GPU가 보이지 않거나 GPU 작업이 CPU로만 실행되면 성공으로 처리하지
않는다.


7. 접속 주소
-------------

설치 호스트에서 브라우저를 열 때는 `localhost`를 사용한다. 다른 PC에서
접속할 때는 `localhost` 대신 Ubuntu 호스트의 IP 주소를 사용한다.

  HOST_IP="$(ip -4 route get 1.1.1.1 | awk '{for (i=1; i<=NF; i++) if ($i=="src") {print $(i+1); exit}}')"
  printf 'HOST_IP=%s\n' "$HOST_IP"

기본 주소:

  FeDiT:              http://HOST_IP:18000/fedit/predictor-creator-tool
  Prediction Manager: http://HOST_IP:18000/prediction-manager/docs
  MLflow:             http://HOST_IP:15000
  NiFi:               http://HOST_IP:15001/nifi/
  Ray Dashboard:      http://HOST_IP:15002
  Label Studio:       http://HOST_IP:15003
  Prometheus:         http://HOST_IP:19090

FeDiT 첫 화면에서 다음 메뉴가 보여야 한다.

- 학습 데이터셋 준비
- 데이터 수집
- 저장소
- NiFi
- Label Studio
- Pipeline
- AutoML
- Ray
- MLflow
- TensorBoard
- Model Registry
- KServe
- MLOps 모니터링


8. 서비스별 선행 조건과 2.2.9 기능 전수 점검
-----------------------

데이터셋 → KFP 재학습:

1. Dataset 메뉴에서 CSV 데이터셋 이름, 학습 유형, target column을 지정한다.
2. 분류는 target label이 정확히 두 종류여야 하며, 회귀는 target 값이 모두
   숫자여야 한다.
3. 버전을 업로드한 뒤 전처리 화면에서 `준비 완료`를 포함해 실행한다.
4. 생성된 준비 완료 버전에서 `파이프라인 입력 생성` → `Pipeline 실행`을 한다.
   작업 Pod는 데이터 다운로드 토큰을 사용해 내부 Prediction Manager 서비스에
   접근한다. Ingress 주소를 직접 입력하거나 인증 헤더를 복사할 필요가 없다.
5. Kubeflow Pipelines Run의 `Succeeded`, MLflow Run과 등록 모델을 확인한 뒤
   시험용 Run, 데이터셋, 등록 모델을 정리한다.

AutoML 결과 원클릭 서빙:

1. AutoML 메뉴에서 데이터셋 경로와 target column을 설정하여 실제 학습을 완료한다.
2. 결과 카드에서 모델 artifact와 점수가 확인된 후보를 선택한다.
3. `서빙`을 눌러 MLflow 모델 등록과 KServe InferenceService 생성을 요청한다.
   설치 스크립트는 이 단계에 필요한 MLServer runtime을 Kubernetes node cache에
   미리 내려받는다. 따라서 최초 서빙도 이미지 pull 때문에 별도 실패하거나
   장시간 무응답 상태가 되지 않아야 한다.
4. KServe 메뉴에서 Ready endpoint를 확인하고, 모델 입력 schema에 맞는 실제
   추론 요청을 수행해 결과를 확인한다.
5. 시험이 끝나면 KServe UI에서 endpoint를 삭제하고, 시험용 AutoML job 및
   임시 PVC를 정리한다.

위 두 흐름은 각각 Dataset/AutoML 화면만 방문해서는 완료로 보지 않는다. 반드시
실행 결과와 종료 후 정리 상태까지 확인한다.

설치가 끝난 뒤 다음 명령으로 기능 전수 점검을 실행한다. 장기 작업은 최대
180초 동안 실제 실행 상태를 확인하며, 그 안에 종료하지 않으면 실행 시작을
기록한 뒤 시험 리소스를 정리한다.

CPU:

  cd "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2"
  sudo ./scripts/scripts/verify-2.2.9-cpu.sh

GPU:

  cd "$INSTALL_HOME/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2"
  sudo ./scripts/scripts/verify-2.2.9-gpu.sh

CPU/GPU 점검은 다음 순서를 각 서비스에 적용한다.

  기능 선택 → 설정 → 실제 실행 → 결과 확인 → 시험 리소스 종료

전수 점검 항목은 Dataset, REST 데이터 수집, PVC, NiFi, Label Studio,
Kubeflow Pipelines, MLflow, Ray, TensorBoard, KServe, AutoML, Prometheus와
Prediction Manager 모니터링을 포함한다. 설치 직후와 재시작 후에 각각 다시
실행하여 14개 실제 동작이 모두 PASS인지 확인한다.


9. 재실행과 로그 확인
----------------------

설치가 중단된 경우 같은 모드의 `01` 또는 `02` 명령을 다시 실행한다.
완료된 단계는 상태 파일을 기준으로 건너뛰고, 중단된 단계부터 이어서 실행한다.

CPU 설치 상태와 결과:

  "$INSTALL_HOME/prediction-manager-work/.prediction-manager/cpu"

GPU 설치 상태와 결과:

  "$INSTALL_HOME/prediction-manager-work/.prediction-manager/gpu"

`01` 스크립트가 즉시 끝난 경우에도 오류라고 단정하지 않는다. 출력의 `[SKIP]`,
`[PASS]`, `[FAIL]`과 마지막에 표시되는 보고서 경로를 확인한다. `[FAIL]`이
있으면 해당 로그를 확인한 뒤 같은 명령을 다시 실행한다.
