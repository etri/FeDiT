FeDiT 예측매니저 GPU/CPU 호스트 설치 가이드
=================================================

문서 범위
---------
- Ubuntu 22.04 LTS x86_64 물리 호스트 또는 VM에 직접 설치하는 기준이다.
- SSH로 접속한 호스트 터미널에서 명령을 실행한다.
- Docker 컨테이너 안에 접속하여 설치하는 방식은 다루지 않는다.
- 설치기는 호스트에 Docker, containerd, Kubernetes 및 필요 서비스를 구성한다.
- 한 호스트에서 GPU 모드와 CPU 모드 중 하나만 선택한다.
- Dataset·AutoML·Ray·MLflow·KServe 등 2.2.9 전체 기능시험은 별도로 수행한다.


1. 설치 전 요구 사항
---------------------

공통 요구 사항:
- Ubuntu 22.04 LTS x86_64
- CPU 4코어 이상
- 메모리 28 GiB 이상
- 루트 파티션 여유 공간 200 GiB 이상
- 인터넷 접속
- sudo 사용 권한
- 새로 설치하거나 예측매니저가 설치되지 않은 호스트 권장

GPU 모드 추가 요구 사항:
- NVIDIA GPU가 호스트에 장착되어 있어야 한다.
- NVIDIA 드라이버가 미리 설치되어 있고 `nvidia-smi`가 정상 실행되어야 한다.
- 이 설치기는 NVIDIA 드라이버를 설치·업데이트·재설치하지 않는다.
- GPU 개수·모델·드라이버·최소 VRAM은 `nvidia-smi`에서 자동으로 읽는다.
- GPU당 time-slicing 슬롯은 최소 VRAM을 12 GiB 단위로 계산하고 1~8개로 제한한다.

CPU 모드:
- NVIDIA GPU와 `nvidia-smi`가 필요하지 않다.
- NVIDIA 드라이버, Container Toolkit, Device Plugin, DCGM Exporter를 설치하지 않는다.
- Ray는 CPU 이미지를 사용하며 Ray GPU worker는 비활성화한다.


2. 호스트 상태 확인
-------------------

아래 명령은 Docker 컨테이너 터미널이 아닌 Ubuntu 호스트 터미널에서
실행한다.

  source /etc/os-release
  printf 'OS=%s %s\nARCH=%s\n' "$ID" "$VERSION_ID" "$(uname -m)"
  printf 'CPU cores: '; nproc
  free -h
  df -h /
  ip -4 route

출력에서 Ubuntu 22.04와 x86_64를 확인한다.

GPU 모드를 선택할 때만 다음 명령을 추가로 실행한다.

  nvidia-smi

`nvidia-smi`가 실패하면 GPU 설치 스크립트를 실행하지 않는다. 드라이버는 이
설치 범위 밖에서 먼저 정상화해야 한다.


3. FeDiT 소스 다운로드
------------------------

호스트에 Git과 기본 도구를 설치한다.

  sudo apt-get update
  sudo DEBIAN_FRONTEND=noninteractive apt-get install -y \
    ca-certificates curl git

고정 작업 폴더를 생성하고 지정된 FeDiT 브랜치를 다운로드한다.

  mkdir -p /home/$USER/prediction-manager-work
  cd /home/$USER/prediction-manager-work
  git clone -b OPFW_development_ETRI_pman --single-branch https://github.com/etri/FeDiT.git

다운로드 결과를 확인한다.

  cd /home/$USER/prediction-manager-work/FeDiT
  git branch --show-current
  test "$(git branch --show-current)" = "OPFW_development_ETRI_pman"
  test -d OPFW/ml_prediction_manager_v2
  test -d OPFW/ml_prediction_manager_v2_frontend

설치 스크립트 위치는 다음과 같다.

  /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts


4. GPU/CPU 모드 선택
---------------------

아래 두 가지 중 하나만 선택한다. 한 호스트에서 GPU용과 CPU용 설치
스크립트를 섞어서 실행하지 않는다.

GPU 모드 실행 파일:
  01-install-required-modules.sh
  02-start-prediction-manager.sh
  생성 설정: .verification-install.env
  상태 저장: /opt/prediction-manager-verification/state

CPU 모드 실행 파일:
  01-install-required-modules-cpu.sh
  02-start-prediction-manager-cpu.sh
  생성 설정: .verification-install-cpu.env
  상태 저장: /opt/prediction-manager-verification-cpu/state

스크립트의 실행 권한을 확보한다.

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  chmod +x 01-install-required-modules.sh 02-start-prediction-manager.sh
  chmod +x 01-install-required-modules-cpu.sh 02-start-prediction-manager-cpu.sh
  chmod +x install-verification.sh scripts/*.sh


5. GPU 모드 설치
------------------

이 절은 GPU 모드를 선택한 호스트에서만 수행한다. 일반 사용자 계정으로
실행하며, 필요한 단계에서 스크립트가 sudo 권한을 요청한다.

5.1 변경 없는 사전 점검

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./01-install-required-modules.sh --dry-run

5.2 필수 모듈 일괄 설치

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./01-install-required-modules.sh

이 단계에서 다음 항목을 호스트에 설치한다.
- Ubuntu 필수 패키지
- Docker, containerd, Docker Buildx
- kubelet, kubeadm, kubectl
- Helm, Kustomize

NVIDIA 드라이버는 정상 동작 여부만 확인하고 변경하지 않는다.

5.3 서비스 설치 및 실행

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./02-start-prediction-manager.sh

서비스 스크립트는 다음 GPU 항목을 자동으로 구성한다.
- NVIDIA Container Toolkit
- 호스트 GPU 개수·모델·드라이버·최소 VRAM 탐지
- Kubernetes NVIDIA Device Plugin
- GPU time-slicing
- DCGM Exporter
- Ray GPU worker


6. CPU 모드 설치
------------------

이 절은 CPU 모드를 선택한 호스트에서만 수행한다. CPU 스크립트는
설정 파일이 복사되어 오거나 수정되어도 GPU 관련 설정을 CPU 안전 값으로
다시 고정한다.

6.1 변경 없는 사전 점검

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./01-install-required-modules-cpu.sh --dry-run

6.2 필수 모듈 일괄 설치

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./01-install-required-modules-cpu.sh

이 단계에서 다음 항목을 호스트에 설치한다.
- Ubuntu 필수 패키지
- Docker, containerd, Docker Buildx
- kubelet, kubeadm, kubectl
- Helm, Kustomize

다음 항목은 설치하거나 검사하지 않는다.
- NVIDIA 드라이버
- NVIDIA Container Toolkit
- Kubernetes NVIDIA Device Plugin
- DCGM Exporter
- Docker GPU 실행 검사

6.3 서비스 설치 및 실행

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./02-start-prediction-manager-cpu.sh

CPU 모드의 Ray는 `rayproject/ray:2.54.1-py312` 이미지를 기반으로 구성되며
CPU worker만 사용한다.


7. 재실행과 중단 복구
--------------------

설치가 중단되면 선택한 모드의 같은 명령을 다시 실행한다. 완료된 단계는
상태 파일을 기준으로 SKIP하고 중단된 단계부터 계속한다.

GPU 모드:

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./01-install-required-modules.sh
  ./02-start-prediction-manager.sh

CPU 모드:

  cd /home/$USER/prediction-manager-work/FeDiT/OPFW/ml_prediction_manager_v2/scripts
  ./01-install-required-modules-cpu.sh
  ./02-start-prediction-manager-cpu.sh

`01` 스크립트가 바로 종료될 때는 출력의 `[SKIP]`, `[PASS]`, `[FAIL]`과 보고서
경로를 확인한다. 이전 실행에서 완료된 단계라면 SKIP 후 정상 종료하는
것이 맞다.


8. 호스트 포트와 접속 주소
-------------------------

설치기는 서비스 접속용 포트를 호스트의 모든 인터페이스에 바인딩한다.
활성화된 UFW 또는 firewalld가 있으면 다음 TCP 포트를 자동으로 개방한다.

  15000, 15001, 15002, 15003, 18000, 18080, 19090, 30080, 30081

호스트 외부에 있는 공유기, 사내 방화벽, 클라우드 보안 그룹은 설치기가
변경하지 않으므로 필요한 접속 범위에 맞게 별도로 허용해야 한다.

호스트 자체의 브라우저에서는 `localhost`를 사용한다. SSH 접속에 사용한 PC의
브라우저에서는 `localhost`가 아니라 Ubuntu 호스트의 IP 주소를 사용한다.

호스트 IP 확인:

  HOST_IP="$(ip -4 route get 1.1.1.1 | awk '{for (i=1; i<=NF; i++) if ($i=="src") {print $(i+1); exit}}')"
  printf 'HOST_IP=%s\n' "$HOST_IP"

실제 호스트 IP가 반영된 접속 주소를 출력한다.

  printf 'FeDiT: http://%s:18080/fedit/predictor-creator-tool\n' "$HOST_IP"
  printf 'Prediction Manager: http://%s:18000/docs\n' "$HOST_IP"
  printf 'Kubeflow: http://%s:30080\n' "$HOST_IP"
  printf 'Keycloak: http://%s:30081/auth\n' "$HOST_IP"
  printf 'MLflow: http://%s:15000\n' "$HOST_IP"
  printf 'NiFi: http://%s:15001/nifi/\n' "$HOST_IP"
  printf 'Ray Dashboard: http://%s:15002\n' "$HOST_IP"
  printf 'Label Studio: http://%s:15003\n' "$HOST_IP"
  printf 'Prometheus: http://%s:19090\n' "$HOST_IP"


9. 설치 후 진입 점검
--------------------

GPU와 CPU 모드 모두 `02` 스크립트 마지막에서 다음 항목을 점검한다.
- Kubernetes API 진입
- Prediction Manager deployment Ready
- Prediction Manager HTTP 진입
- Kubeflow HTTP 진입
- 선택한 하드웨어 모드 확인

추가로 호스트에서 다음 명령을 실행한다.

  kubectl get nodes -o wide
  kubectl get pods -A
  curl -I --max-time 10 http://127.0.0.1:18000/docs
  curl -I --max-time 10 http://127.0.0.1:18080/fedit/predictor-creator-tool

GPU 모드에서는 다음 명령도 실행한다.

  nvidia-smi
  kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"  nvidia.com/gpu="}{.status.allocatable.nvidia\.com/gpu}{"\n"}{end}'

CPU 모드에서는 `nvidia-smi`와 `nvidia.com/gpu`를 성공 조건으로 사용하지 않는다.


10. 설치 결과 확인
------------------

GPU 모드 상태·설정·보고서:
  /opt/prediction-manager-verification/state
  /opt/prediction-manager-verification/generated
  /opt/prediction-manager-verification/results

CPU 모드 상태·설정·보고서:
  /opt/prediction-manager-verification-cpu/state
  /opt/prediction-manager-verification-cpu/generated
  /opt/prediction-manager-verification-cpu/results

설치 실패 시 터미널에 출력된 `[FAIL]` 항목과 보고서·로그 경로를 먼저
확인한다. 원인을 조치한 후 선택한 모드의 같은 `01` 또는 `02` 명령을
다시 실행한다.
