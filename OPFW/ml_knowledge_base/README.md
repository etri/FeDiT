# Knowledge Base Repository

이 저장소는 **FeDiT/OPFW** 프로젝트의 체계적인 지식 관리 및 자료 정리를 위해 설계되었습니다. 아래는 디렉토리 구조와 각 폴더의 용도에 대한 설명입니다.

---

## 디렉토리 구조

```
knowledge_base/
│
├── doc/                # 문서 자료
│   ├── 01_requirements # 프로젝트 요구사항 문서
│   ├── 02_design       # 설계 문서
│   └── 03_manual       # 사용자 매뉴얼
│
├── release/            # 릴리즈 파일 및 관련 자료
│   ├── 01_Middleware   # 미들웨어 릴리즈 파일
│   └── 02_Web          # 웹 릴리즈 파일
│
├── src/                # 소스 코드 및 디자인 리소스
│   ├── design          # 디자인 파일
│   ├── middleware      # 미들웨어 관련 코드
│   └── web             # 웹 관련 코드
│
└── README.md           # 저장소 개요 파일
```

---

### **폴더 설명**

#### `doc/`
- **목적**: 프로젝트 관련 문서, 시스템 아키텍처, 기능 명세, 사용자 가이드를 보관합니다.
- **하위 폴더**:
  - `01_requirements`: 프로젝트 요구 사항 문서
  - `02_design`: 설계 문서 및 다이어그램
  - `03_manual`: 사용자 매뉴얼 및 가이드라인

#### `release/`
- **목적**: 릴리즈 빌드, 배포 파일 및 변경 로그를 보관합니다.
- **하위 폴더**:
  - `01_Middleware`: 미들웨어 릴리즈 파일
  - `02_Web`: 웹 릴리즈 파일

#### `src/`
- **목적**: 프로젝트 소스 코드 및 디자인 파일을 보관합니다.
- **하위 폴더**:
  - `design/`: 디자인 리소스 (예: `.jsp` 파일)
  - `middleware/`: 미들웨어 관련 코드
  - `web/`: 웹 애플리케이션 코드

---

### **기여 방법**
1. 저장소 클론:
   ```bash
   git clone <repository-url>
   ```
2. 수정할 디렉토리(`doc/`, `release/`, `src/`)에서 작업을 진행합니다.
3. 변경 사항 추가:
   ```bash
   git add <파일 또는 폴더>
   ```
4. 변경 사항 커밋:
   ```bash
   git commit -m "변경 사항 설명 추가"
   ```
5. 변경 사항 푸시:
   ```bash
   git push origin <브랜치 이름>
   ```

---

### **참고사항**
- 모든 문서 자료는 `doc/` 디렉토리에 최신 상태로 유지하세요.
- `release/` 폴더에 릴리즈 자료를 추가할 때는 버전 관리 기준을 준수하세요.
- `src/` 디렉토리의 코드 및 파일 구조를 깔끔하게 유지하세요.
