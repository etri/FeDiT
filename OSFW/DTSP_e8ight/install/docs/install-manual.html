01준비

Docker Engine 20.10 이상 + Compose v2 가 설치된 서버. 이미지 레지스트리에 접속하지 않는다 — insecure-registries 설정도 docker login 도 필요 없다.

이미지 묶음은 이미 들어 있다. 파일이 있는지만 확인한다.

ls -lh images/union-twin-service-images.tar.gz   # 약 1.9GB

저장소를 서버에 두고 install 로 이동한다.

git lfs install
git clone <저장소> /opt/DTSP_연합
cd /opt/DTSP_연합/install

03설치

백엔드를 먼저 올리고 프론트를 올린다. 프론트의 BFF 가 백엔드의 PostgreSQL 을 쓰기 때문이다. 각 스크립트는 앞 단계가 뜰 때까지 기다린 뒤 상태와 다음 단계를 출력한다. 여러 번 실행해도 안전하다.

000-init.sh백엔드 · 포트 점검, 네트워크·디렉터리 생성, 이미지 묶음 적재 — 3~10분
011-db.sh백엔드 · PostgreSQL · MongoDB · Redis — 30초
022-kafka.sh백엔드 · Zookeeper · Kafka · 토픽 생성 — 최초 1회 이미지 빌드 5~10분 (인터넷 필요)
033-ndxpro.sh백엔드 · 코어 9개 + 파일 서비스 + FDT 뷰어 — 2분
041-front.sh프론트 · 화면(fe) + 자체 서버(BFF) — 30초
cd fdt-service-backend
./install/0-init.sh
./install/1-db.sh
./install/2-kafka.sh
./install/3-ndxpro.sh

cd ../fdt-service-frontend
./install/1-front.sh          # 프록시 없으면 --expose, 프록시까지 올리려면 --nginx
이미지 준비

0-init.sh 가 images/union-twin-service-images.tar.gz 를 적재한다. 파일은 이미 들어 있으므로 따로 받거나 만들 필요가 없고, 푸는 명령을 직접 칠 필요도 없다.

갱신본을 받았거나 이미지가 지워졌을 때만 직접 쓴다 — ./scripts/images-load.sh <파일>, 확인은 ./scripts/check-images.sh.

Kafka·Zookeeper 도 묶음에 포함돼 있어 빌드하지 않는다. 소스코드가 있다면 --build 로 직접 빌드할 수도 있다.

04확인

cd fdt-service-backend
./scripts/health.sh

브라우저에서 PUBLIC_URL 접속 → /signin 으로 이동한다. 계정은 admin@e8ight.co.kr / .env 의 ADMIN_SEED_PASSWORD 값.

05이미지 묶음 (사내 작업)

설치 담당자는 건너뛴다

묶음은 이미 저장소 루트에 들어 있고 0-init.sh 가 적재한다. 이 절은 묶음을 새로 만들거나 새 이미지가 올라와 갱신하는 사내 담당자를 위한 것이다.

# 사내에서 — 묶음 만들기
cd image-bundle
cp bundle.env.example bundle.env    # 레지스트리 계정 또는 소스코드 경로
./fetch-from-registry.sh            # 방법 A — 사내 레지스트리에서 받기
./build-from-source.sh              # 방법 B — 소스코드에서 빌드
./pack.sh                           # out/union-twin-service-images.tar.gz

# 설치 서버에서 — 적재
./install/0-init.sh                 # 묶음 적재 + 이미지 점검

새 이미지가 올라왔을 때는 전체를 다시 말지 않고 바뀐 것만 보낸다.

./fetch-from-registry.sh 172.16.28.217:12000/union-twin-fe:latest
./pack.sh --only 172.16.28.217:12000/union-twin-fe:latest --name union-twin-fe-20260819.tar.gz

# 설치 서버에서
./scripts/images-load.sh ../images/union-twin-service-images-fe-20260820.tar.gz
../fdt-service-frontend/scripts/remake_container.sh union-twin-fe front/compose.yml
아키텍처 주의

맥(Apple Silicon)에서 묶음을 만들면 공개 이미지 6개와 직접 빌드한 Kafka·Zookeeper 가 arm64 가 되어 리눅스 서버에서 exec format error 가 난다. image-bundle/pack.sh 가 전부 linux/amd64 인지 저장 직전에 검사하고, 다르면 파일을 만들지 않고 중단한다.

./scripts/check-images.sh 로 필요한 이미지가 다 있는지, 아키텍처가 이 서버와 맞는지 확인할 수 있다.

cd ../fdt-service-backend && ./install/9-clean.sh --data   # 백엔드 + 데이터 전체

--all--data + 내려받은 이미지

08Windows 서버

이미지는 전부 linux/amd64 다. 컨테이너 안은 리눅스로 고정이라 호스트 OS 는 상관없지만, 설치 스크립트가 bash 라서 Windows 에서는 WSL2 안에서 실행해야 한다.

호스트동작방식
Linux x86_64그대로네이티브
Windows됨WSL2 (내부에 리눅스 커널)
macOS Intel됨Docker Desktop 리눅스 VM
macOS Apple Silicon됨, 느림Rosetta 에뮬레이션
Linux arm64안 됨이미지가 amd64 전용

중요한 것은 OS 가 아니라 CPU 아키텍처다. arm64 서버에는 올릴 수 없다.

# 관리자 PowerShell
wsl --install -d Ubuntu-22.04

# WSL 안에서
sudo apt update && sudo apt install -y docker.io docker-compose-v2
sudo usermod -aG docker $USER          # 로그아웃 후 재접속

git config --global core.autocrlf input
git lfs install
git clone <저장소> ~/DTSP_연합       # /mnt/c/... 아님. WSL 파일시스템 안에
cd ~/DTSP_연합/install

이후 절차는 리눅스와 동일하다.

주의

/mnt/c/... 에 두면 I/O 가 느리고 파일 권한이 꼬여 볼륨 마운트가 실패한다. .env 의 REPO 도 WSL 내부 경로로 둔다.

Docker Desktop 을 쓴다면 Linux containers 모드여야 한다. Windows containers 모드로는 동작하지 않는다.

WSL2 는 기본적으로 localhost 만 열린다. 외부 접속은 netsh interface portproxy 로 포워딩하거나, Windows Server 2022 이상이면 .wslconfig 에 networkingMode=mirrored 를 넣는다. HOST 에는 WSL IP 가 아니라 Windows 서버의 IP 를 적는다.

09로컬 실행 (개발용)

NDXPro 백엔드는 서버 것을 쓰고 화면만 로컬에 띄운다.

cd fdt-service-frontend
docker compose --env-file ../.env -f front/compose-local.yml up -d   # localhost:50028
