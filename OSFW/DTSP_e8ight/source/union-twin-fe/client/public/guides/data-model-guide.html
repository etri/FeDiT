01

기본 흐름

속성은 속성 관리에서 카탈로그(이름·값 타입·설명)로 먼저 등록하고, 데이터 모델링에서 모델에 골라 넣습니다. 속성이 일반 값인지, 관계인지, 위치인지(Type)는 카탈로그가 아니라 모델 안에서 정합니다. 같은 속성이라도 모델마다 다른 Type으로 쓸 수 있습니다.

  1. 속성 관리 → New : ID, Value Type(String · Double · …), Title, Description 등록. 시계열용 observedAt, 단위 unitCode는 이미 등록되어 있어 새로 만들 필요가 없습니다.
  2. 데이터 모델링 → New : Type(모델 이름), Title, Description 입력.
  3. Edit → Add attribute : 카탈로그에서 속성을 골라 추가. 트리에서 속성을 클릭하면 오른쪽 패널에서 Type / Value Type / Enum / model Type을 편집.
  4. Save 후 검증하고, 수집을 시작할 준비가 되면 Ready. Ready 이후에는 Version up 전까지 수정할 수 없습니다.

속성 종류 3가지

Property

일반 값

온도, 이름, 상태처럼 값을 그대로 담는 속성. 하위에 observedAt을 붙이면 시계열(관측) 속성이 됩니다.

Relationship

관계

다른 엔티티를 가리키는 속성. 값은 대상 엔티티의 URN이며, 패널의 model Type에서 대상 모델을 고릅니다. 예: hasTwin

GeoProperty

위치

GeoJSON 좌표를 담는 속성. Type을 GeoProperty로 바꾸면 Format이 GeoJSON, Value Type이 POINT 등 도형 타입으로 바뀝니다. 예: location

패널의 Type 셀렉트는 Edit 모드에서만 열립니다. Type을 바꾸면 Value Type · Format · model Type이 그 종류의 기본값으로 초기화되므로, 바꾼 뒤 값을 다시 확인하세요.
02

시계열(관측) 속성

센서값처럼 시간마다 새 값이 들어오는 속성은 하위 속성 observedAt을 붙여 표시합니다. 이렇게 정의된 속성은 저장 시 모델의 observation 목록에 자동으로 오르고, 모델은 동적 모델(isDynamic: true)이 되어 엔티티 조회에서 시간 조건·이력 조회가 가능해집니다.

화면에서 만들기

  1. Edit 모드에서 Add attribute로 값 속성(예: temp, Double)을 추가합니다.
  2. 트리에서 temp 행을 선택하면 오른쪽에 나타나는 Add child 버튼을 누릅니다.
  3. 목록에서 observedAt을 선택합니다. (observedAt · unitCode는 하위 속성으로만 추가할 수 있습니다.)
  4. 트리에 temp > observedAt이 생기면 Save. 관측값 속성마다 1–3을 반복합니다.
observedAt은 모델 최상위가 아니라 각 관측 속성의 하위에 둡니다. 최상위에 두면 관측 시각이 특정 속성과 묶이지 않아 시계열로 인식되지 않습니다.

저장되는 모델 JSON

attributes.temp
{
  "temp": {
    "type": "Property",
    "valueType": "Double",
    "childAttributeNames": { "observedAt": "ngsi-ld:observedAt" },
    "childAttributes": {
      "observedAt": { "type": "Property", "valueType": "String", "format": "DateTime" }
    }
  }
}
// 저장 후 서버가 계산 → "observation": ["temp"], "isDynamic": true

Translator · 조회

Translator에서는 값 속성에 observedAt 메타데이터를 함께 넣습니다. 노코드 매핑에서는 observedAt 옵션(현재 시각 / 원천 필드)을 고르면 아래 코드가 생성됩니다.

translate() 발췌
LinkedHashMap<String, String> observedAtMdNames = new LinkedHashMap<>();
observedAtMdNames.put("observedAt", "e8ight:observedAt");
List<Attribute> observedAtMd = new ArrayList<>();
observedAtMd.add(new Attribute("observedAt", null, ZonedDateTime.now(ZoneOffset.UTC), null, null));

attrs.add(new Attribute("temp", "Property", item.getDouble("temp"), observedAtMdNames, observedAtMd));
curl · 시간 조건 조회 (주소는 예시)
curl 'http://ndxpro-server:54011/ndxpro/v1/broker/entities/iot/temporal?type=PohangAtmosphere&timeproperty=observedAt&timerel=after&time=2026-09-17T00:00:00Z&limit=50'
03

관계(Relationship) 속성

다른 엔티티를 참조하는 속성입니다. 값은 대상 엔티티의 URN(urn:ngsi-ld:{Type}:{id})이고, 모델에는 어떤 모델을 가리킬 수 있는지(modelType)를 기록합니다. 연합 트윈의 hasTwin이 대표적인 예입니다.

화면에서 만들기

  1. Edit 모드에서 Add attribute로 관계 이름의 속성(예: hasTwin, refBuilding)을 추가합니다. 카탈로그에 없으면 속성 관리에서 Value Type String으로 먼저 등록합니다.
  2. 트리에서 그 속성을 클릭하고 패널의 Type을 Relationship으로 바꿉니다. Value Type은 String으로 고정됩니다.
  3. model Type 선택기에서 대상 모델을 검색해 고릅니다(여러 개 가능). 선택하면 urn:ngsi-ld:{Type}: 형식으로 저장되고, 배지를 누르면 해당 모델 페이지로 이동합니다.
  4. Save.
단일 트윈 통합으로 만든 연합 모델은 hasTwin이 이미 Relationship + 연결 단일 모델로 채워져 있으므로 이 절차가 필요 없습니다.

저장되는 모델 JSON

attributes.hasTwin
{
  "hasTwin": {
    "type": "Relationship",
    "valueType": "String",
    "modelType": ["urn:ngsi-ld:KR1011170001:", "urn:ngsi-ld:KR1011180001:"]
  }
}

Translator · 조회

Translator에서는 kind를 "Relationship"으로 주고 값에 대상 URN을 만듭니다. 노코드 매핑에서는 속성 종류를 Relationship으로 두고 대상 URN prefix를 입력하면 됩니다. 관계 속성에는 observedAt 메타데이터를 붙이지 않습니다.

translate() 발췌
attrs.add(new Attribute("hasTwin", "Relationship",
    "urn:ngsi-ld:KR1011170001:" + item.getString("childId"), null, null));
브로커 조회 결과
"hasTwin": {
  "type": "Relationship",
  "object": ["urn:ngsi-ld:KR1011170001:KR-101117-0001", "urn:ngsi-ld:KR1011180001:KR-101118-0001"]
}
04

위치(GeoProperty) 속성

  1. Add attribute로 location을 추가합니다. 카탈로그의 location은 GeoJSON용으로 등록되어 있어 Type이 바로 GeoProperty로 들어옵니다.
  2. 다른 이름을 쓰려면 패널에서 Type을 GeoProperty로 바꿉니다. Format은 GeoJSON, Value Type은 도형 종류(POINT · POLYGON · LINE_STRING 등)에서 고릅니다.
  3. Save.
attributes.location
{
  "location": {
    "type": "GeoProperty",
    "valueType": "POINT",
    "format": "GeoJSON"
  }
}
translate() 발췌
JSONObject point = new JSONObject()
    .put("type", "Point")
    .put("coordinates", new JSONArray()
        .put(item.getDouble("lon"))
        .put(item.getDouble("lat")));
attrs.add(new Attribute("location", "GeoProperty", point, null, null));
GeoJSON 좌표 순서는 [경도, 위도]입니다. 위도·경도를 따로 담는 일반 속성(LATITUDE, LONGITUDE)과 혼동하지 마세요.
05

체크리스트

증상확인할 것
엔티티 조회에서 시간 조건·이력 탭이 안 보임관측 속성 하위에 observedAt이 있는지, 저장 후 모델 observation에 이름이 올라왔는지
관계 속성 값이 문자열로만 보임모델에서 Type이 Relationship인지, Translator kind가 "Relationship"인지
model Type 배지를 눌러도 이동하지 않음대상 모델이 삭제되었거나 이름이 바뀐 경우 — 선택기에서 다시 고름
위치가 지도에 안 찍힘Type GeoProperty + Format GeoJSON인지, 좌표 순서가 [경도, 위도]인지
Type 셀렉트가 열리지 않음Edit 모드인지, Ready 상태면 Version up 후 편집
