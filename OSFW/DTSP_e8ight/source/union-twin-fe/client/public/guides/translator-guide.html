Translator 코드 작성

AI에게 요청할 때 필요한 준비물 3종

아래 세 가지를 세트로 전달하면 결과 정확도가 크게 올라갑니다.

입력 1

원천 데이터 샘플

실제 들어오는 JSON 1건. 필드명, 타입, 배열/객체 구조, 시간 필드 유무를 여기서 읽습니다.

입력 2

데이터 모델

목표 NGSI-LD 스키마. entity type, id prefix, attribute 이름, valueType, 메타데이터를 정의합니다.

입력 3

샘플 Translator 코드

코드 골격과 컨벤션. Attribute / Entity / EntityId 생성자 사용법을 잡아줍니다.

프롬프트 템플릿

prompt
아래 원천 데이터와 데이터 모델을 참고해서 Translator 코드를 만들어줘.
샘플 Translator 코드의 구조와 컨벤션을 그대로 따라줘.

[1] 원천 데이터
<원천 JSON 붙여넣기>

[2] 데이터 모델
<모델링 JSON 붙여넣기>

[3] 샘플 Translator 코드
<Test.java 붙여넣기>

조건:
- 클래스명은 모델의 type과 동일하게 (예: Todos3)
- entity id는 모델의 id prefix + 원천 데이터의 식별자
- 원천 데이터에 시간 필드가 없으면 observedAt은 현재 시간(UTC) 사용

입력 데이터

원천 데이터
{
  "userId": 1,
  "id": 1,
  "title": "delectus aut autem",
  "completed": false
}
데이터 모델 (요약)
{
  "id": "urn:ngsi-ld:Todos3:",
  "type": "Todos3",
  "attributeNames": {
    "userId": "e8ight:userId",
    "completed": "e8ight:completed",
    "title": "e8ight:title"
  },
  "attributes": {
    "userId":    { "valueType": "Integer" },
    "title":     { "valueType": "String"  },
    "completed": { "valueType": "Boolean" }
  }
}

모델 → 코드 매핑

모델 필드코드에서 쓰이는 곳
type클래스명, EntityId의 두 번째 인자
idEntityId의 URN prefix
attributeNamesLinkedHashMap<String, String> attrNames
attributes[].typeAttribute 생성자의 두 번째 인자 (Property / Relationship)
attributes[].valueTypegetInt() / getString() / getBoolean() 선택 기준
childAttributes.observedAt메타데이터 observedAt 생성

완성 코드

Todos3.java
package kr.co.e8ight.ndxpro.translatorRunner.translator;

import kr.co.e8ight.ndxpro.translatorRunner.vo.Attribute;
import kr.co.e8ight.ndxpro.translatorRunner.vo.Entity;
import kr.co.e8ight.ndxpro.translatorRunner.vo.EntityId;
import org.json.JSONObject;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.time.ZoneOffset;
import java.time.ZonedDateTime;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;

public class Todos3 extends EntityTranslator {

    private static final Logger log = LoggerFactory.getLogger(Todos3.class);

    public Todos3(String modelType) {
    }

    @Override
    public List<Entity> translate(JSONObject jsonObject) {

        List<Entity> entities = new ArrayList<>();

        //// 수정 구간 시작

        // 1. NGSI-LD Attribute Name Map
        LinkedHashMap<String, String> attrNames = new LinkedHashMap<>();
        attrNames.put("userId", "e8ight:userId");
        attrNames.put("title", "e8ight:title");
        attrNames.put("completed", "e8ight:completed");

        // 2. Entity ID 생성
        int id = jsonObject.getInt("id");
        EntityId entityId = new EntityId(
                "urn:ngsi-ld:Todos3:" + id,
                "Todos3",
                "UOS"
        );

        // 3. observedAt Metadata (원천에 시간 필드가 없으므로 현재 시간 사용)
        LinkedHashMap<String, String> observedAtMdNames = new LinkedHashMap<>();
        observedAtMdNames.put("observedAt", "e8ight:observedAt");

        List<Attribute> observedAtMd = new ArrayList<>();
        ZonedDateTime zonedDateTime = ZonedDateTime.now(ZoneOffset.UTC);
        Attribute observedAt = new Attribute("observedAt", null, zonedDateTime, null, null);
        observedAtMd.add(observedAt);

        // 4. Attribute 생성
        List<Attribute> attrs = new ArrayList<>();

        Attribute userId = new Attribute(
                "userId", "Property", jsonObject.getInt("userId"),
                observedAtMdNames, observedAtMd);
        attrs.add(userId);

        Attribute title = new Attribute(
                "title", "Property", jsonObject.getString("title"),
                observedAtMdNames, observedAtMd);
        attrs.add(title);

        Attribute completed = new Attribute(
                "completed", "Property", jsonObject.getBoolean("completed"),
                observedAtMdNames, observedAtMd);
        attrs.add(completed);

        // 5. Entity 생성
        Entity entity = new Entity(entityId, attrNames, attrs);
        entities.add(entity);

        //// 수정 구간 종료

        return entities;
    }
}
주의. 위 예시는 observedAtMd 리스트를 세 attribute가 공유합니다. attribute마다 observedAt이 달라져야 하는 모델이라면 리스트를 각각 생성하세요.

작성 규칙

Attribute 생성자 시그니처

signature
new Attribute(
    "attributeName",   // 1. 속성 이름
    "Property",        // 2. Property / Relationship (메타데이터는 null)
    value,             // 3. 값 (Property=실제 값, Relationship=대상 URN)
    mdNames,           // 4. 메타데이터 이름 Map (없으면 null)
    mdList             // 5. 메타데이터 Attribute List (없으면 null)
);

valueType → JSON getter

모델 valueType코드
IntegerjsonObject.getInt("field")
StringjsonObject.getString("field")
BooleanjsonObject.getBoolean("field")
Double / NumberjsonObject.getDouble("field")

// (A) 원천에 시간 필드가 있는 경우 — 파싱 + KST → UTC 변환
ZonedDateTime zonedDateTime = LocalDateTime

Relationship 작성 패턴

Property가 값을 담는다면, Relationship은 다른 엔티티의 URN을 담습니다.

단일 관계 (1:1) — 메타데이터 포함

1:1
Attribute hasBuilding = new Attribute(
        "hasBuilding",
        "Relationship",
        "urn:Building:" + jsonObject.getString("buildingId"),   // ← 대상 엔티티 URN
        hasBuildingMdNames,
        hasBuildingMd
);
attrs.add(hasBuilding);

다중 관계 (1:N)

1:N
List<String> targets = new ArrayList<>();
JSONArray ids = jsonObject.getJSONArray("buildingIds");
for (int i = 0; i < ids.length(); i++) {
    targets.add("urn:Building:" + ids.getString(i));
}

Attribute hasBuildings = new Attribute("hasBuildings", "Relationship", targets, null, null);
attrs.add(hasBuildings);

메타데이터 없을 때

no metadata
Attribute hasBuilding = new Attribute("hasBuilding", "Relationship", "urn:Building:001", null, null);
Relationship도 attrNames에 등록해야 합니다. — attrNames.put("hasBuilding", "e8ight:hasBuilding");
